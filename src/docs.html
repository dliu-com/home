Technical architecture

Home Tasks records when recurring jobs at home were last done: laundry, guinea pig cleaning, hanging clothes and brushing Kaka's teeth. The pages are static files; one small Lambda function records, lists and deletes the times, and nothing runs while nobody is using the site.

API

RequestWhat it does
GET /api/timestamps?task=laundryReturns the task's latest 10 records, newest first.
POST /api/timestamps {"task":"laundry"}Records the server's current time. 201 on success, 409 within an hour of the last record.
DELETE /api/timestamps {"task":"laundry","id":"…"}Deletes a record that is less than an hour old. 403 once it is older.

Task names are laundry, guinea-pigs, hang-clothes and kaka-teeth. Every API response is sent with cache-control: no-store.

Data

Each record is an item with the task as its partition key and timestamp#request-id as its sort key, so a query returns a task's records in time order. A separate <task>-control item holds the latest time for each task; the record and the control item are written in one transaction whose condition fails if the control item is less than an hour old. That makes the one-hour rule hold even when two people press Record at the same moment.

How tasks work

Each task has a rolling target: it should be recorded again within that many hours of the last record.

TaskRecord it afterTarget
Laundrystarting the laundryevery 40 hours
Guinea pig cleaningcleaning the cage and kitchen area for all six guinea pigsevery 70 hours
Hang clotheshanging up the clothesevery 45 hours
Kaka's teethbrushing Kaka's teethevery 100 hours
  • The server records the time. A task cannot be recorded twice within one hour; other tasks are not affected.
  • A record can be deleted only during its first hour, after the browser asks for confirmation.
  • Each task page shows its 10 most recent records, newest first, in the visitor's time zone.

The full rules are on the Rules page.

Cost

Every part is billed per use, so the site costs next to nothing while nobody is using it.

  • No servers, NAT gateways, load balancers or API Gateway: nothing has a fixed monthly fee.
  • Lambda, DynamoDB on-demand, S3 and CloudFront are charged by requests, storage, run time and data transfer.
  • The TLS certificate is free, and the Route 53 hosted zone is shared with the other dliu.com sites.
  • Pages are cached at the edge for up to a day; app.js and styles.css for 5 minutes in the browser. Each deploy clears the cache once.

Security

The site holds only task names and times. It has no accounts and no sign-in.

  • Anyone who can open the site can record a task and delete a record during its first hour. The one-hour rules are enforced on the server, not only in the browser.
  • The site bucket blocks all public access; CloudFront reads it through an origin access identity.
  • All traffic is HTTPS; plain HTTP is redirected.
  • The Lambda function can read and write only its own table. Requests for an unknown task are rejected.
  • The table is retained if the CloudFormation stack is deleted, so records survive a redeploy.
